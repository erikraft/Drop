# ErikrafT Drop™ - Onion Gateway

This directory contains the Tor Onion Gateway configuration and entrypoint scripts to run ErikrafT Drop™ as a Tor v3 Onion Service alongside the standard HTTPS Web Service on Render Free (or any Docker environment).

---

## How It Works

1. **Single Container Execution:** The container runs both Tor (in the background) and ErikrafT Drop™ Node.js server.
2. **Port Forwarding:** Tor listens for incoming Onion Service connections on port 80 and forwards them locally to `127.0.0.1:$PORT` (where ErikrafT Drop™ listens).
3. **Persistence via Secret:** The Tor private key (`hs_ed25519_secret_key`) is stored as a Base64-encoded string in the `ONION_PRIVATE_KEY_BASE64` environment variable/Secret in Render.
4. **Dynamic Address Discovery:** The application reads the hidden service `hostname` generated by Tor and exposes the `.onion` domain securely to the frontend via the `/api/onion-info` API endpoint.

## Generating the First `.onion` Identity

To generate a new `.onion` private key:

### Option A: Generating via Render Logs (One-time setup)
1. In the Render Dashboard, set the environment variable:
   ```env
   GENERATE_ONION_KEY=true
   ```
2. Deploy the service.
3. Check the Render deployment logs for the lines:
   ```text
   [ONION] Tor connected
   [ONION] Onion Service started
   [ONION] Hostname: xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.onion
   [ONION] Base64 Encoded Private Key for ONION_PRIVATE_KEY_BASE64 secret:
   <BASE64_STRING>
   ```
4. Copy the `<BASE64_STRING>`.
5. Remove `GENERATE_ONION_KEY` from Environment Variables.
6. Add the secret under Render Environment Variables:
   - **Key:** `ONION_PRIVATE_KEY_BASE64`
   - **Value:** `<BASE64_STRING>`

### Option B: Generating Locally via Tor
1. Install Tor locally (`sudo apt install tor` or `brew install tor`).
2. Run Tor with a temporary hidden service directory:
   ```bash
   tor --HiddenServiceDir ./temp_onion --HiddenServicePort 80 127.0.0.1:3000
   ```
3. Stop Tor once `./temp_onion/hs_ed25519_secret_key` and `./temp_onion/hostname` are generated.
4. Convert the private key to Base64:
   ```bash
   base64 -w 0 ./temp_onion/hs_ed25519_secret_key
   ```
5. Store the Base64 output in Render as `ONION_PRIVATE_KEY_BASE64`.
6. Delete the local `./temp_onion` folder securely.

## Setting Up on Render Dashboard

1. Go to your Web Service settings in [Render Dashboard](https://dashboard.render.com).
2. Set the **Build Command** / Dockerfile path to:
   `onion-gateway/Dockerfile`
3. Under **Environment Variables**, add:
   - `ONION_PRIVATE_KEY_BASE64`: *(Your Base64 encoded private key)*
4. Deploy the service.

## Testing & Verification

1. **Normal Domain:** Visit `https://drop.erikraft.com` - should work normally.
2. **Tor Browser:** Open Tor Browser and visit `http://xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.onion`.
3. **HTTP & WebSocket:** Verify file transfers, room creation, pairing, and chat work over both standard Web and `.onion`.
4. **Redeploy Test:** Trigger a manual redeploy on Render and verify that the `.onion` hostname remains identical.

---

## Disabling Tor Onion Service

If you wish to temporarily disable the Tor Onion Service without breaking ErikrafT Drop™:
1. Remove or unset `ONION_PRIVATE_KEY_BASE64` in Render Environment Variables.
2. The service will log a warning and run ErikrafT Drop™ normally on HTTPS.
