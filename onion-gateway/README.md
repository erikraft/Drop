# ErikrafT Drop™ - Tor Onion Service Gateway

This directory contains the Tor Onion Gateway configuration and entrypoint scripts to run ErikrafT Drop™ as a Tor v3 Onion Service alongside the standard Web Service on Render (or any Docker environment).

---

## Architecture Overview

1. **Single Web Service Container:** The same Render Web Service runs both Tor (in the background) and the ErikrafT Drop™ Node.js server.
2. **Domain Integrity:** The domain `https://drop.erikraft.com` remains unchanged.
3. **Port Binding:** Tor listens for incoming Onion Service connections on port 80 and forwards them internally to `127.0.0.1:$PORT` (where ErikrafT Drop™ listens).
4. **Persistence via Secret:** Storing the Base64-encoded `hs_ed25519_secret_key` in the `ONION_PRIVATE_KEY_BASE64` environment variable ensures the `.onion` hostname never changes across redeploys or service restarts.
5. **Non-blocking Startup:** ErikrafT Drop™ starts listening on `$PORT` immediately upon container launch, ensuring Render health checks pass without delay.
6. **Public API Discovery:** The `/api/onion-info` endpoint exposes only public Onion information (`hostname` and status) to the frontend UI. Private keys are never exposed via logs or API endpoints.

## Generating & Setting Up Your `.onion` Identity

### Safe Key Generation (Recommended - Offline)

To generate a new persistent `.onion` address locally:

1. Install Tor on your local machine (`sudo apt install tor` or `brew install tor`).
2. Run Tor with a temporary directory:
   ```bash
   tor --HiddenServiceDir ./temp_onion --HiddenServicePort 80 127.0.0.1:3000
   ```
3. Once Tor generates `./temp_onion/hs_ed25519_secret_key` and `./temp_onion/hostname`, stop Tor (`Ctrl+C`).
4. Convert the private key to Base64 using the included script:
   ```bash
   node scripts/generate-onion-key.js ./temp_onion/hs_ed25519_secret_key
   ```
5. In your Render Web Service settings, add an Environment Variable / Secret:
   - **Key:** `ONION_PRIVATE_KEY_BASE64`
   - **Value:** *(The Base64 string generated by the script)*
6. Delete the local `./temp_onion` folder securely.

## Render Dashboard Configuration

To run Tor Onion Gateway on Render:

1. Open your Web Service in [Render Dashboard](https://dashboard.render.com).
2. Ensure **Environment** is set to `Docker`.
3. Set **Dockerfile Path** to:
   `onion-gateway/Dockerfile` (or keep default `Dockerfile`, as both now include Tor support).
4. Under **Environment Variables**, configure:
   - `ONION_PRIVATE_KEY_BASE64`: *(Your Base64 encoded private key)*
   - `WS_FALLBACK`: `true` *(Enables WebSocket fallback for browsers like Tor Browser where WebRTC is restricted)*
5. Deploy or restart the Web Service.

## Testing & Verification

1. **Standard HTTPS Access:** Visit `https://drop.erikraft.com` - functions normally.
2. **Tor Browser Access:** Open Tor Browser and navigate to `http://[ONION_HOSTNAME].onion`.
3. **Features Check:** Verify file transfer, room creation, pairing, and chat work seamlessly across both HTTPS and Tor.
4. **Persistence Check:** Trigger a manual redeploy in Render; confirm the `.onion` address remains identical.
